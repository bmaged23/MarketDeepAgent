# Project scripts

Run modules from the repository root. The folders describe their purpose:

| Folder | Main tools |
|---|---|
| `evaluation/` | `build_dataset.py` authors frozen references; `run_suite.py` executes scenarios; `judge_answers.py` scores replies; `check_gate.py` enforces coverage and quality; `export_langsmith.py` uploads traces and feedback. |
| `performance/` | `benchmark_embeddings.py` measures inference and resources; `build_report.py` generates public JSON, chart and performance guide while retaining final release measurements. |
| `release/` | `evaluate_image.py` evaluates the actual candidate; `smoke_image.py` checks HTTP/model/state/persistence; `publish_image.py` verifies image identity before publication. Stack and Docker adapters support these entry points. |
| `runtime/` | `provision.py` initializes/indexes an empty catalog in a short-lived process; `serve.py` starts the application and synchronization watcher. |

Dataset authoring is an explicit maintainer action, not automatic regeneration during a release. Application feature CLIs stay beside their services under `app/`.

Diagram/demo tools stay with the GitHub Pages site in `docs/`. Docker Hub documentation is generated by `python docs/dockerhub/generate_readme.py`. See the [folder guide](../docs/guides/PROJECT_STRUCTURE.md).

Private recordings, model/tool traces, credentials and scratch outputs belong in ignored `.evaluation-local/` or `.release-local/`, never sibling project folders. Published sanitized aggregate evidence belongs in `evaluation/results/` and `docs/performance/`.
